# نظام البصمة – الحرية هايبر ماركت الإنشائية (نسخة الاستضافة المستقلة)

## الملفات
| الملف | وظيفته |
|---|---|
| `index.html` | الواجهة الكاملة (نفس التصميم والوظائف: بصمة، تعديل الأوقات، طلب بصمة، الرواتب، تقارير Word، الزون) |
| `firebase-config.js` | إعدادات مشروعك في Firebase (**تعدّله أنت**) |
| `shim.js` | يربط الواجهة بقاعدة بيانات Firebase |
| `login.js` | تسجيل دخول حقيقي: الموظف برمز، والمسؤول باسم ورمز |
| `firestore.rules` | قواعد الأمان (من يقرأ/يكتب ماذا) |
| `firebase.json` | إعداد الاستضافة |

## المتطلبات (كلها مجانية ضمن خطة Spark)
- حساب Google + مشروع Firebase (بدون بطاقة بنكية).
- **قاعدة البيانات:** Cloud Firestore.
- **تسجيل الدخول:** Firebase Authentication (Email/Password).
- **الاستضافة:** Firebase Hosting (رابط HTTPS دائم: `https://PROJECT_ID.web.app`). HTTPS ضروري لعمل GPS.
- Node.js لتشغيل أداة النشر مرة واحدة.

## خطوات التشغيل
1. من console.firebase.google.com أنشئ مشروعاً جديداً.
2. **Build ← Authentication ← Get started ← Sign-in method:** فعّل **Email/Password**.
3. **Build ← Firestore Database ← Create database** (اختر Production mode وأقرب منطقة).
4. **Project settings ← Your apps ← Web (</>)**: سجّل تطبيقاً وانسخ الإعدادات داخل `firebase-config.js`.
5. في الطرفية داخل هذا المجلد:
   ```
   npm install -g firebase-tools
   firebase login
   firebase use --add        # اختر مشروعك
   firebase deploy           # ينشر الموقع وقواعد الأمان معاً
   ```
6. افتح الرابط الذي يظهر، واضغط **دخول المسؤول**، واكتب الاسم والرمز الذي تريده. **أول دخول ينشئ حساب المسؤول ثم يُقفل الإنشاء** – افعلها فوراً بعد النشر قبل أن يعرف أحد الرابط.
7. من لوحة المسؤول: حدّد الزون (وأنت داخل الشركة)، أضف الموظفين، واضبط الرواتب.

> إذا استضفت الملفات خارج Firebase (Netlify / GitHub Pages / Cloudflare Pages) فانشر القواعد من الكونسول (Firestore ← Rules ← الصق `firestore.rules`) وأضف نطاقك في **Authentication ← Settings ← Authorized domains**.

## كيف يعمل الدخول
- **الموظف:** يكتب رمزه فقط (يُحوَّل داخلياً إلى حساب Firebase، والرموز تُحفظ بأحرف صغيرة a-z و0-9).
- **المسؤول:** اسم + رمز (4 خانات فأكثر؛ يفضّل رمز أطول). الاسم يُتحقق منه من الواجهة، والرمز هو كلمة المرور الفعلية في Firebase.
- حذف موظف يلغي تفعيله فوراً ولا يستطيع بعدها استخدام النظام، لكن حسابه يبقى في Authentication (حذفه الكامل يدوي من الكونسول).

## ما الذي يحتاج خادماً خلفياً (غير متوفر بدونه)
هذه حدود حقيقية للنسخة المجانية بلا خادم؛ لم أغيّر أي وظيفة لكنها ليست مضمونة 100%:
1. **توقيت البصمة والزون يُحسبان في متصفح الموظف:** موظف تقني يستطيع التلاعب بالوقت أو بالموقع. الحل: Cloud Functions تتحقق بتوقيت الخادم (تتطلب خطة Blaze، وفيها حصة مجانية لكن تطلب بطاقة).
2. **الإشعارات الفورية لطلب البصمة:** تعمل الآن فقط والصفحة مفتوحة. الإشعار مع التطبيق المغلق يحتاج Firebase Cloud Messaging + Functions.
3. **حذف حساب الدخول نهائياً** وإعادة تعيين الرموز تلقائياً.
4. **حماية قوية من تخمين الرموز:** Firebase يحدّ المحاولات، لكن الرموز القصيرة ضعيفة؛ استخدم رموزاً أطول إن أمكن.
5. **تعديل الأوقات من المسؤول والتقارير والرواتب:** تعمل كلها من المتصفح (لا تحتاج خادماً) والمسؤول فقط يملك صلاحية الكتابة بحسب القواعد.

## الحدود المجانية (Spark) تقريباً
50 ألف قراءة و20 ألف كتابة يومياً في Firestore، وهذا يكفي عشرات الموظفين بسهولة.
